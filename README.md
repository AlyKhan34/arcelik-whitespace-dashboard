# Arçelik store white-space dashboard

**Where does Arçelik have demand without a store?** For each of Türkiye's 973 districts (ilçe),
the dashboard shows how many households live there, how well-off they are, how many homes are
sold, and how many Arçelik stores serve them. A simple, documented score (0–100) ranks the
districts, and rule-based flags mark the ones that need attention. Above all, these are
**high-score districts with no store** ("white space").

Coursework for ECON 449 (Arçelik AI use cases, use case 08). It is descriptive analysis only: no
forecasting, no machine learning, no optimisation. This is not an Arçelik product.

> ⚠️ **The store data is dummy.** The 3,391 stores in `data/stores_dummy.csv` were generated by
> `scripts/make_stores.py` (seed 449). Bigger and richer districts get more stores, and a few gaps
> were planted for the demo. Population, households, housing sales and the income proxy are real
> public data. A real store list can replace that one file without code changes.

## Open it

Download [`dist/whitespace_dashboard.html`](dist/whitespace_dashboard.html) and double-click it.
It is one self-contained file: the data and the chart library are embedded, so it works offline
in any modern browser. Use the EN / TR switch in the sidebar to change the language.

| Page | Answers |
|---|---|
| **Overview** | How does the store network cover households? Where are demand and stores? Which regions are under- or over-served? (KPIs, district bubble map, "where to look first", trends, stores per 100k households by region) |
| **Ranking & flags** | Which districts should we look at first? (top 20, combinable flags, sortable and searchable table with CSV export) |
| **District** | Why does a district score high, and what is there today? (score components, 36-month housing sales, store list, peer districts) |
| **Method & data** | How is every number computed? (editable score weights, flag rules, formulas, sources, assumptions) |

The filters (region, province, SEGE tier, store format, year 2023–2025, store month) are kept in
the link, so a view can be shared.

## Score and flags

Each input is turned into a percentile rank over all 973 districts. Then
**score = 40% households + 30% income (SEGE-2022) + 30% housing sales per 1,000 households**.
Stores are not part of the score, so "high score, no store" is a clean signal.

| Flag | Rule |
|---|---|
| 🔴 White space | score ≥ 70 and no active store |
| 🟠 Under-served | score ≥ 60, at least 1 store, and stores per 100k households below 50% of the national figure |
| 🟡 Housing boom | housing sales up ≥ 25% year on year, ≥ 10,000 households, at most 1 store |
| ⚪ Over-served (info) | score < 30 and stores per 100k households above 2× the national figure |

In the default view (2025, stores as of Oct 2026) there are 3,069 active stores, 10.97 per 100k
households nationally, and 30 white-space districts. Rank 1 is Esenyurt (İstanbul).

## Data sources

| Data | Source | Period |
|---|---|---|
| Population, average household size | TÜİK ADNKS (address-based population register), via MEDAS | 31 Dec 2023, 2024, 2025 |
| Housing sales | TÜİK MEDAS "İlçe Konut Satış Sayıları" | monthly, Jan 2023 – Dec 2025 |
| Income proxy | SEGE-2022 district development index, Ministry of Industry and Technology | 2022 (used for every year) |
| Map positions | District centres, [nejdetkadir/turkish_cities](https://github.com/nejdetkadir/turkish_cities) | current |
| Province outlines | [alpers/Turkey-Maps-GeoJSON](https://github.com/alpers/Turkey-Maps-GeoJSON), simplified | current |
| Arçelik stores | **Dummy**, generated by `scripts/make_stores.py` (seed 449) | Jan 2008 – Oct 2026 |

The assumptions behind these sources are explained on the dashboard's Method page and in
[`docs/data_dictionary.md`](docs/data_dictionary.md). For example, households are computed as
population ÷ household size, and SEGE-2022 stands in for income. The original downloads are in
`data/raw/`.

## Build and test

You need Python 3 with pandas, and Node.js.

```bash
npm install                          # once: ECharts 5.6.0 (inlined into the page) + Playwright
npx playwright install chromium      # once, for the tests and the PDF
npm run build                        # -> dist/whitespace_dashboard.html
npm run test:parity                  # in-browser metrics vs scripts/metrics.py, 2023/2024/2025
npm run test:ui                      # filters, empty states, offline, EN/TR at 1280/390 px
npm run handin                       # -> dist/note.pdf, dist/whitespace_data.zip
```

| Folder | Content |
|---|---|
| `data/` | Cleaned CSVs and raw downloads |
| `scripts/` | Data preparation, `metrics.py` (reference implementation), `build_dashboard.py` (score weights and flag thresholds in `CONFIG`), `handin.py` |
| `site/` | Page templates: `index.html`, `app.js`, `metrics.js`, `i18n.js`, `styles.css` |
| `tests/` | `parity.mjs`, `ui.mjs` |
| `docs/` | `design.md` (the brief), `data_dictionary.md`, `note.md` (one-page note) |
| `dist/` | Built dashboard and the one-page note (PDF) |
